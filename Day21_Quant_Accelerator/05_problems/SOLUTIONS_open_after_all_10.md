# Solutions
1. The lower bound. You're least sure of the point estimate, and Kelly punishes overestimating the edge far more than underestimating it. Since lower-bound Kelly is 0, size is a risk budget (money you can lose), capped at 1.0×. *Size from what you can prove, not what you hope.*
2. It trains you to ignore it. When it finally fires for a real reason, you'll override it "like always". *An alarm that always rings is a silent alarm.*
3. The strategy's worst historical day is about −5.9%. A bootstrap only reshuffles history, so anything beyond the worst day shows 0%. A crash day like Mar 2020 (NIFTY −13% on 23 Mar 2020) can happen. *Resampling can't invent the tail.*
4. A halt stops new risk and forces a look, without trading. "Liquidate on −6%" is a stop-loss: a new, untested strategy bolted on (Carver's equity-curve tests: it usually hurts). *Don't let the risk layer become an untested second strategy.*
5. It would retire a working strategy on noise: two bad years are entirely normal at SR 0.18. Use drawdown depth and plumbing failures, not time. *At low Sharpe, time under water is not evidence.*
6. (a) No check comparing orders sent vs intended → duplicate-tag check + position mismatch; (b) no limit on order volume → max orders/day + max order value; (c) slow manual shutdown → KILL file any human can create. Also a dead flag reused → version pinning (Day 23). *Every disaster is a missing assertion.*
7. Above the broker-specified orders-per-second threshold (10 OPS per segment per exchange in the NSE standards, per Zerodha's summary). You send a few orders per month, roughly 10^6 times below it. Static IP + 2FA still apply. *Know which rules bind you and which don't.*
8. (1) Halt (automatic). (2) Don't trade to "fix" it. (3) Pull the broker's tradebook and order log. (4) Find the source: a missed fill callback, a manual app trade, a duplicate? (5) Correct the BOOK to match reality, write an incident note, add a test that reproduces it, then reset the halt. *Reconcile first, trade later.*
9. The position stays (halts never trade). On decision day, no new orders go out while halted; if the signal says "stay long", nothing would happen anyway. If it said "exit", the exit is a risk-reducing order: decide in the rulebook NOW whether exits are allowed during a halt (the engine allows `risk_exit`). *Decide edge cases before they arrive.*
10. "Amendment A1, <date IST>: capital at risk ₹X → ₹Y. Reason: <not P&L>." Then a 48-hour cooling-off, outside market hours, re-hash rulebook.json, update RULEBOOK.md, and mentor sign-off. A raise justified by one good month gets rejected: one month is noise. *Never resize on recent P&L.*
