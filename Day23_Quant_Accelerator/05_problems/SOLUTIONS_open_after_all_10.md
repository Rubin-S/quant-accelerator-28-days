# Solutions
1. Catches: a signal using today's close (look-ahead), and a wrong decision-day rule (e.g. last session of the month). Misses: anything both share, like the same wrong data file or the same cost model error. *Parity proves agreement, not truth.*
2. It matches the tested backtest (Day 15 timing) and gives a whole session to check data and preflight. Trading on t itself would be a NEW timing, so pre-register it and re-run the stress/holdout first. *Live code runs the tested rule, not a better idea.*
3. Integer units, fee rounding, and cash sitting idle while sizing to a limit with a cushion. A red flag is a gap that grows in steps on specific days (a missed or doubled order) or exceeds the cost of one round trip per year. *Small and smooth is rounding; jumps are bugs.*
4. The index open is computed, not traded; NIFTYBEES opening prints are thin and noisy (Day 14); real spreads and queue position don't exist in daily OHLC. *Daily bars can't tell you about fills.*
5. Saving ≈ 0.25% × ~2 trades a year ≈ 0.5% a year at most, against 7 days out of the market or in at the wrong time, which cost ~0.4%/yr CAGR here and adds tracking error. Not worth it for a 2-trades-a-year rule. *Don't haggle over pennies on a slow strategy.*
6. A retry after a crash produces the SAME tag, so the duplicate guard (and the broker's order book) shows it was already sent. Random IDs make every retry look new: that's Knight. *Idempotency needs a key you can recompute.*
7. A crash mid-write leaving a half-written, unparseable state, so the next run starts with garbage or crashes. `os.replace` is atomic on the same filesystem. *Never update in place what you can't afford to corrupt.*
8. On start: fetch today's broker orders by tag, find the order, record its real status/fill, reconcile holdings, then continue. Never resend blindly. If the broker can't be reached, halt. *After a crash, ask the broker, not your memory.*
9. In replay there's no human to write the incident note, so it's simulated. Live, the halt is the system asking for a person; auto-clearing it would make it decoration. *Halts end with a human decision.*
10. Latency: preflight + run finish well before 15:15. Traffic: orders/day (expect 0, maybe 1). Errors: rejects, exceptions, failed checks (expect 0). Saturation: disk, token validity, rate-limit headroom. *Monitor the symptoms you'd act on.*
